# 3D CG Visual Style

本文件是 Auto-Storyboard 的动漫 3D CG 视觉风格参考层。它不替代分镜生成和审核主规则，只改变画面媒介、资产提示词口径和固定尾部风格词。

## 使用边界

- 3D CG 只改变视觉媒介、资产提示词口径和固定尾部风格，不改变当前 run 的主分镜合同。
- 竖屏 run：保留竖屏主合同中的 `组首空间锁定`、组尾衔接、时间段、对白对象、视频禁止项、真实 reviewer 和校验流程。
- 横屏 run：不使用旧竖屏字段 `组首空间锁定`。第一帧状态、人物站位、左右关系、视线方向、关键道具位置，写入 `**组间承接**` 或 `**横屏构图/调度**`。
- 横屏 run 必须继续保留 `**运镜强化词**`、`**Seedance执行提示补充**` 和 `**--neg**`。
- 不改剧情、不删台词、不改变人物关系。
- 不把真人实拍、摄影机现场拍摄、真实演员、纪录片摄影等真人媒介词写进 3D CG run。
- 不把动漫、二次元、卡通渲染、轮廓线等目标媒介特征写进负向词。
- 不输出模型说明、参考图占位、模板编号、`@图片/@视频/@音频`。
- `视频禁止项` 仍写剧情错误，不写通用画质词或媒介风格词。

## 分镜画面口径

3D CG run 的镜头描述应服务于可动画化的动漫 CG 场景：

- 人物：二次元角色设计，风格化面部和眼睛，清晰轮廓线，表情绑定自然，口型同步清楚，身体动作有重心和关节逻辑。
- 渲染：高质量卡通渲染，PBR 材质与手绘质感融合，不写真人皮肤质感、真实演员妆造或摄影棚实拍。
- 材质：布料纹理、纸张纤维、金属反光、木材纹路、玻璃反射等可渲染属性可以保留，但要服务动漫 CG 画面，不要变成写实照片。
- 光影：电影级布光、自然景深、柔和环境光和少量风格化高光按剧情需要使用，不堆特效。
- 场景：空间结构、道具位置、人物站位仍要具体，避免变成概念场景图。
- 动作：复杂动作按阶段拆开，写清位移、遮挡、递接物和道具状态，避免穿模和抢动作。
- 特效：使用视觉峰值特效，让画面在剧情峰值处更有动漫 CG 冲击力；视觉峰值不只来自打斗，也来自关键道具、身份、权力、危险、环境、心理或信息落点，特效不得离开当前剧本自行表演。

## 分镜提示词附加特性

worker 在 3D CG run 中写 `镜头描述` 和 `光影设计` 时，应把下列特性作为自然画面语言融入正文：

- 角色外观用动漫 CG 口径：风格化眼睛、清晰五官轮廓、发型体块明确、服装边缘干净。
- 表演用可动画化口径：眼神方向明确、眉眼变化清楚、嘴型与台词同步、手指和肩颈动作不过载。
- 镜头用动漫短剧口径：中近景优先保证脸部表情和口型，关键反转可用轻微推近或低角度压迫，但不写炫技运镜。
- 光影用渲染口径：轮廓光、柔和环境光、道具反光、角色边缘高光可以用于增强层次，但必须服务剧情。
- 动作稳定性用 CG 口径：复杂肢体动作、保护站位、递接道具必须拆清，避免穿模、手指畸形、道具穿透身体。

## 横屏运镜口径

横屏 3D CG run 不要只把视觉风格换成动漫 CG。每组应至少有 1 个有明确路径或落点的可见运镜，用来制造 16:9 空间层次、视差和情绪冲击：

- 可用：横向跟拍、前景掠过、半环绕、贴地推进、低角度推近、焦点转移、急停落点。
- 运镜必须绑定人物走位、武器/道具揭示、危险进入、压迫峰值或情绪反转，不要只写“固定机位”“稳定中景”到底。
- 对白密集组仍要保留稳定中景、稳定过肩或近中景承载口型；可用短促推近、焦点转移或前景遮挡增强节奏，不要每个镜头都炫技运动。

## 视觉峰值特效规则

动漫 3D CG run 允许比真人短剧更有冲击力，但特效只用于强化剧情峰值，不得把短剧变成游戏技能展示、廉价仙侠宣传片或满屏光污染。视觉峰值不只来自打斗，也可以来自动作冲击、关键道具显影、身份揭示、权力压场、危险进入、环境异变、心理冲击、信息落点或情绪爆点。

总原则：

- 特效要有画面冲击，但必须服务当前剧本的强节拍和剧情落点。
- 特效必须绑定具体人物、动作、武器、道具、地面、空气、衣物、碎石、烟尘、环境状态、心理压力或信息落点，不能悬空堆词。
- 不写法阵、法术光球、技能 UI、游戏图标、满屏粒子、过曝光束、遮脸光效、特效盖住主体。
- 特效不替代动作。每个时间段仍然要写清谁移动、谁出手、谁受力、道具怎么变化、落点在哪里。
- 特效不能乱堆。普通对白组、低密度情绪组不强行加特效；只有动作、对峙峰值、危险进入、关键道具冲击、身份/权力压场、环境异变、心理冲击、信息落点或情绪爆点才加。

通用视觉峰值类型：

1. 动作 / 受力反馈
   - 视觉事件必须沿人物动作、道具边缘、接触点或空气层出现，并让退步、震动、裂纹、灯火或人群反应形成反馈。

2. 道具 / 证据显影
   - 微光、反光、纹路亮起或屏幕/纸面状态变化必须服务“信息被看见”，不能变成独立魔法表演。

3. 身份 / 权力压场
   - 用环境光、前景遮挡、人物肩背僵住、衣摆或灯火受压来表现权力变化，保持脸部和口型清楚。

4. 危险 / 环境异变
   - 烟雾、警示灯、门窗震动、裂纹、腐蚀或材质反应必须有物理来源、影响对象和组尾状态。

5. 心理 / 信息落点
   - 心理异象、背景压暗或短促边光只能围绕人物眼神、关键道具、信息落点和反应收束。

仙侠、玄幻、古武、强者归来等题材的落地出场 / 压场特效、武器/身法、灵物、暗器和近身交锋示例，放在横屏 generator 的 `TOPIC_PACKS.md` 对应题材包中；公共 3D CG 媒介层不要把这些母题强行迁移到无关剧本。

### 视觉峰值写法

视觉峰值不是固定触发词表。不要因为某个题材词机械加特效，也不要因为没有题材词就漏掉当前剧本里的强节拍。判断依据是当前剧本、项目包、视觉风格说明和本组剧情功能。

写 `镜头描述` 和 `光影设计` 时，beat / hero 级视觉峰值至少考虑：

- 来源：由谁的动作、哪件道具、哪句揭示、哪个环境异常、哪股心理压力或哪条信息触发。
- 主视觉：观众看见的可执行视觉事件，例如边缘冷光、暗金微光、空气波纹、烛火伏低、道具纹路亮起。
- 路径：视觉事件沿刀锋、地面、桌面、屏幕、衣摆、空气层或人物视线从哪里到哪里。
- 持续：用可执行的正向强度写法，例如压住 1-2 秒、沿动作半弧线掠过，或在组尾留下余波。不要反复用“极弱、很小、一闪即灭、低范围”削弱本该成立的视觉峰值；这些词只能偶尔用于 `atmosphere` 或普通 `beat`，不能支撑 `hero`。
- 反馈：谁后退、谁僵住、什么道具震动、灯火如何变化、人群如何反应。
- 收束：最后落到人物表情、道具状态、空间余波、危险结果或新信息上。
- 运镜配合：推近、半环绕、贴地推进、焦点转移或急停落点如何跟随路径和反馈。

## 高视觉化题材特效口径

如果当前剧本属于仙侠、玄幻、古武、强者归来等高视觉化题材，或任何存在动作、道具、身份、权力、危险、环境、心理或信息状态突变的强节拍，3D CG 画面默认应比真人短剧更有可见能量感。特效要克制，但不能只靠固定 `画面风格` 尾部；强节拍必须进入镜头正文或光影设计。

这不是固定触发词表。不要因为某个题材词机械加特效，也不要因为没有题材词就漏掉当前剧本里的动作、道具、身份、权力、危险、环境、心理或信息状态突变。

需要判断的强节拍类型：

- 动作或受力结果发生变化。
- 关键道具、证据、凭证、药物、武器、设备或屏幕结果改变局势。
- 身份、权力、危险、环境、心理、信息或情绪状态发生明显变化。
- 空间被动作、压力、光源、烟尘、警示灯、门窗震动或人群反应改变可见状态。

可用素材只是示例，不是触发条件。公共 3D CG 层只固定判断维度：来源、主视觉、路径、持续、反馈、收束和运镜配合；题材专属的武器、身法、灵物、暗器、落地压场素材，应从横屏 generator 的 `TOPIC_PACKS.md` 中按需启用。

字段落点：

- `镜头描述` 写来源、路径、影响、反馈和收束结果。
- `光影设计` 写颜色、范围、亮度、持续时间和主体可见性。
- `运镜强化词` 写镜头如何跟随气流、边缘冷光、尘浪、关键道具微光、心理异象或受力落点。
- `Seedance执行提示补充` 写“特效服务动作/道具/压迫，不遮脸、不盖口型、不生成法阵、光球、技能 UI 或满屏粒子”。

正文要优先写正向可控强度：特效贴着动作路径、道具边缘、地面裂纹、灯火伏低、衣摆受压或人群反应推进；限制性要求放进 `--neg` 的视觉峰值特效条件负面。不要在镜头正文里反复用“极弱、很小、一闪即灭、低范围”把强节拍写成看不见的小光点。

hero 不是“有一个特效点”，而是“本组有一个主视觉事件”。如果声明 `hero`，正文至少 3 层可见反馈落地：

1. 主视觉形态：光、气、裂纹、压迫、道具显影、环境异变或心理/信息落点。
2. 人物/道具受力：倒飞、停住、塌陷、断裂、下坠、低头、安心、失控等状态变化。
3. 环境反馈：尘浪、烛火、青石裂纹、衣摆、火光、桌面、地面尘粒或人群反应。
4. 运镜配合：推近、贴地跟随、急停、焦点转移、低角度压场等镜头动作。
5. 结果收束：特效收住后，局势变化、人物关系或道具状态被确认。

### 视频模型友好特效

写 `hero` 前先选择主视觉承载方式：身体外层、隔空能量间隙、道具表面、外层护体壳、地面反馈、环境光影或心理异象。承载方式决定特效长在哪里，不能只在画面中央堆“真气、冷光、气流”。

近身接触、格挡、截腕、接拳、搀扶、接人或拖拽等高风险动作，优先写隔空半寸、隔空能量间隙、外层护体壳受力、道具表面受力；如果必须接触，要写清相对位置和谁主动谁被动，避免手掌穿过拳头、手臂融合或接触点被烟雾遮住。

避免普通能量球和白烟化：`hero` 主视觉不得退化为普通圆形能量球、白烟团或电纹贴图。必须写清受力方向、材质属性、附着对象、环境反馈和结果反馈，例如透明壳、琉璃裂纹、金属裂光、暗金纹路、压缩冲击面、折射边缘、火光压暗、尘粒外推、衣袖反震、地面裂纹或人群后缩。

3D CG 视觉峰值镜头的光影设计模板：主视觉镜头的 `光影设计` 至少写清主光源、特效光材质、主次关系、作用范围、环境反馈中的三项。不要通过“极弱、很小、一闪即灭”保持主体清楚；应写成强烈但有来源，沿动作路径、道具外层、护盾边缘或地面反馈展开，人物脸部和口型不被遮挡。

hero 爆点曲线：`hero` 主视觉镜头必须有触发前压迫、爆发帧 / 慢动作冲击帧、扩散路径、场景级反馈和余波收束中的大多数阶段。允许使用“高规格国漫番剧级战斗特效”“体积光余波”“屏幕边缘轻微震颤”“压暗全场主光半秒”等强度锚点，但必须绑定本组动作、道具、护体外壳、地面或环境光影，不能变成无来源满屏光污染。镜头组织优先写成触发镜头、冲击镜头、余波展示镜头。

视觉峰值特效条件负面：

以前可能会写“全压法阵、粒子、光效”一类笼统负面；动漫 3D CG run 应改成按风险选择的具体错误：

不要把“强光效、大片特效、强能量、粒子、光效”作为负面词。只禁错误形态，不禁强度本身。

- 廉价页游特效
- 无来源满屏粒子
- 过曝吞没人物面部
- 遮挡口型的强光
- 特效盖住主体动作路径
- 游戏技能 UI
- 法阵文字
- 魔法阵贴图
- 角色被光束吞没或遮脸

推荐组合句：

`高质量动漫3D CG短剧风格，二次元角色设计，风格化面部与眼睛，清晰轮廓线，高质量卡通渲染，PBR材质与手绘质感融合，电影级布光，景深自然，按本组视觉峰值/特效重点使用剧情服务型动漫 CG 特效，特效必须绑定动作、道具、身份、权力、环境、心理或信息落点，主体始终清楚。`

## 固定尾部

固定尾部规则按画幅分工，避免横屏 worker 误用竖屏收集策略：

- 竖屏：收集阶段统一追加 3D CG 固定尾部，worker 不要逐组重复写。
- 横屏：`final.txt` 每组必须直接包含 3D CG 版 `**画面风格**` 和 `**--neg**`，不得沿用真人实拍尾部。

竖屏收集阶段使用的固定尾部为：

`画面风格：高质量动漫3D CG短剧风格，二次元角色设计，风格化面部与眼睛，清晰轮廓线，高质量卡通渲染，PBR材质与手绘质感融合，电影级布光，景深自然，表情绑定细腻，口型同步清楚，动作流畅，按本组视觉峰值/特效重点使用剧情服务型动漫 CG 特效，特效必须绑定动作、道具、身份、权力、环境、心理或信息落点，主体始终清楚，无字幕，无配乐`

基础负面词只禁止低质量 CG 与成片污染问题，例如低多边形、廉价游戏建模、穿模、骨骼错位、面部僵硬、眼神空洞、口型错位、材质粗糙、贴图拉伸、轮廓线抖动、字幕、水印、logo 等。无来源满屏粒子、过曝吞没人物面部、遮挡口型的强光、特效盖住主体动作路径、游戏技能 UI、法阵文字、魔法阵贴图、廉价页游特效等属于视觉峰值特效条件负面，只有本组存在相关风险时才按需加入。横屏和竖屏都不要再把 `3D渲染`、`CG感`、`动画感`、`卡通`、`动漫`、`二次元` 作为通用负面词。

## 资产提示词口径

3D CG 资产表应把资产写成可复用动漫 CG 生产资产：

- 人物基础资产：动漫 3D 角色模型设定，角色比例、年龄段、体态、二次元脸型、风格化眼睛、面部稳定特征、发型体块、气质，不写短暂表情。
- 服装资产：建模可用的层次、颜色、材质、磨损、布料纹理和配饰。
- 人物状态：换装、脏污、湿身、受伤、年龄阶段等作为状态，不把临时表情或手势入库。
- 场景基础资产：动漫 3D 空镜环境资产，无人、无人脸、无人群，写空间结构、材质、核心陈设、光线和风格化渲染层次。
- 场景状态：白天、夜雨、断电、破损后、整洁后等作为同一场景状态。
- 道具基础资产：关键道具的 3D 模型设定，材质、尺寸感、形状、文字限制。
- 道具状态：破损、沾湿、盖章、摊开、折皱、散落等作为状态。

## 推荐负面口径

按需选择，不要每个提示词机械堆满：

- 低多边形
- 廉价游戏建模
- 塑料玩具感
- 面部僵硬
- 表情死板
- 眼神空洞
- 口型错位
- 穿模
- 骨骼错位
- 手指畸形
- 材质粗糙
- 贴图拉伸
- 轮廓线抖动
- 多余文字
- 水印
- logo

视觉峰值特效条件负面，只有相关组按需补充：

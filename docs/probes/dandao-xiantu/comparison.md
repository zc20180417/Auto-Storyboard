# 《丹道仙途》探针提示词与当前分镜规则对比

> 结论先行：当前规则作为“分镜审核母版 + Seedance 2.5 提交提示词编译合同”是合理的，已经比单独照搬 v1 或 v2 更适合生产。它可以继续做小规模真实视频探针，但还不应因为本地校验通过就直接放大到前 10 集批量提交。真实 Seedance 视频、口型、特效和跨段连续性仍需在有授权素材和真实 provider 的环境中验证。

## 1. 对比范围与证据边界

本文件中的“第一版”指用户后来明确偏好的资产前置版，即 [probe-v1-first-preferred.md](probe-v1-first-preferred.md)。为了避免版本混淆，同时保留了最早的详细版 [probe-v0-initial.md](probe-v0-initial.md) 和按官方指南压缩的 [probe-v2-current.md](probe-v2-current.md)。

| 版本 | 本项目中的定义 | 主要用途 |
|---|---|---|
| v0 | 最早三探针的详细动作/VFX 基线 | 回看最初的仙侠效果语义和失败边界 |
| v1 | 资产前置第一版：资产清单、读取规则、完整画风、细时间线、原生音频、长负面约束 | 确认资产可核对性和用户偏好的表达密度 |
| v2 | 参考 Seedance 2.5 官方指南压缩的后一版 | 确认正向结构、参考素材映射、连续时间轴和少量约束的方向 |
| 当前规则 | 专属 profile + generator + reviewer + project pack + 提交编译器 | 将 `final.txt` 母版与真实 provider 提交 prompt 分层，并加入世界状态承接 |

这些文件是提示词方案档案，不是视频证据。仓库不保存或伪造 Ark/CPA/ManJuWeb 任务 ID、素材上传回执或输出视频；本地 fixture、逻辑素材绑定和 `validate-episode` 也不能证明真实生成成功。

## 2. 逐项比较

| 维度 | v1（第一版） | v2（压缩版） | 当前规则的取舍与判断 |
|---|---|---|---|
| 整体画风 | 明确写出“写实材质＋克制卡通轮廓”、PBR、低饱和色盘、动漫五官，并在每条探针中重复较完整的风格说明。 | 仍保留风格关键词，但把静态外观复述明显压短。 | 当前把画风固定为命名 preset `realistic-material-restrained-anime-outline`，在每组保留完整整体画风说明。这样既能锁住媒介，又避免每个资产再次改画风；方向正确。 |
| 资产是否前置 | 已把“本次引用的资产”放在提示词开头，A1/A2 等编号和用途都可人工核对，但属于扁平列表，且人物、场景、道具和 VFX 混在一套编号中。 | 改成“参考素材映射／图片1…”，更短，但仍是扁平映射；资产职责容易被压缩成一句话。 | 当前提交层按“人物资产／场景资产／道具与关键视觉资产”三类前置，并逐项写“只参考什么”。这是最适合真实上传顺序、素材审计和后续复盘的结构。 |
| `final.txt` 与提交 prompt | v1 本身就是可复制提交文本，资产编号、上传规则和 provider 操作混在一起。 | v2 仍接近可直接复制的模型 prompt，后来才补充母版/提交层区分。 | 当前 `final.txt` 明确资产无关，不出现 `@图片`、Ark ID 或 provider 字段；素材权利、上传序列化和门禁通过后，编译器才生成 `submission_prompt`。这是必须保留的边界。 |
| 组间空间承接 | v1 的三条探针主要依靠单条视频内部时间线和最后状态，未形成通用的相邻组世界状态合同。 | v2 仍主要写“全程保持”，没有覆盖下一组看不见的多人、道具和轴线状态。 | 当前以文字 `组尾衔接 → 下一组组间承接` 为连续性真源，记录空间锚点、每名在场/画外人物、道具归属与状态、VFX 残留、轴线、机位、光线和声场。尾帧只作可选局部 reference，不能从单人特写推断全场。这个修正直接解决分段生成的 B 点跳变风险。 |
| 动态 VFX 因果链 | v1 对灵火、禁制、焦渣→药液→药材和银光来源写得很细，因果链完整，但文本较长。 | v2 压缩为“按某图形态”“沿炼制路径逆向”等主链，阅读负担小，却可能丢失边界、反馈或收束细节。 | 当前强制在实际时间段内写 `来源 → 形态 → 路径 → 作用对象 → 反馈 → 收束 → 声音`，允许删静态材质复述，不允许删动态中间态、作用边界和收束。对仙侠题材这是比“关键词数量”更可靠的折中。 |
| 运镜自由度 | v1 给每个探针预设推近、环绕、切换等镜头动作；可读性强，但会把模型锁进人工设计的路径。 | v2 仍保留少量“推近／半环绕”等动词，和官方指南的简化方向相近。 | 当前不设每组运镜字段或数量指标，Seedance 2.5 根据主体、动作、构图和节奏自行选合理运动；只有轴线、复杂位移或剧情理解确实需要时才写最少约束。这个取舍符合用户反馈，也避免为凑格式强行运动。 |
| 时间轴 | v1 采用细分的连续段落，例如 0–3、3–6、6–9 秒，动作顺序和状态落点清楚；部分镜头同时承载多个说明。 | v2 采用更简洁的 0–3、3–6、6–10 等时间段，保持连续整数秒，但压缩后某些 VFX 中间态不够显眼。 | 当前固定 4–30 秒整数生成单元、整数镜头时长、从 0 秒首尾相接且总和严格相等；按稳定叙事状态切组，不在回溯、位移或多人重排中硬切。时间合同合理，但 G03/G07/G09/G11 等高密度组仍要以真实视频验证。 |
| 原生音频 | v1 独立写出环境底噪、动作拟音、炉火/药液声、回溯声和对白，覆盖最完整。 | v2 保留“声音”段，表达更短，能防止提示词过长。 | 当前把对白口型、声源方位、底噪、动作声、特效声和静默直接放回发生它们的时间段；默认无 BGM，特效声必须对应可见来源。这样保留 v1 的可执行性，又不新增独立执行章节。 |
| 负面约束 | 每条探针包含较长的通用负面大包，能防止很多错误，但可能抑制火焰、银光、粒子等目标效果，并增加模型负担。 | 按官方指南大幅减少，只保留少量固定边界；风险是极端情况下漏掉本组关键错误。 | 当前 `--neg` 只放本组 2–5 个、以人物/道具/空间为锚点的具体失败风险； reviewer 仍保留完整检查清单。把“审核规则”与“生成反向约束”分开，是更合理的生产做法。 |
| 提示词长度与模型负担 | 三条可复制 prompt 约 7.4k 字符（不含说明性正文），信息完整但重复较多。 | 三条核心 prompt 约 3.7k 字符，模型负担小，但部分仙侠语义被压扁。 | 当前采用“参考资产负责静态稳定、时间轴负责动作、少量硬边界负责防错、reviewer 负责全量检查”的四层结构。长度不追求越短越好，而追求每个词有明确执行职责。 |
| 可审核性与复盘 | v1 人工对照资产很方便，但编号与职责不利于跨集扩展。 | v2 便于阅读，却较难从短句还原资产职责和连续性证据。 | 当前三类资产字段、世界状态承接和 reviewer taxonomy 能分别定位问题；需继续确保 G05→G06 的身份令牌/资产归属写得足够明确。 |
| 事实边界 | v1 有“只允许列出的资产”和“不要新增剧情”，但没有独立的 project pack 隔离层。 | v2 开始强调参考素材与动作层分离，项目专属事实仍需额外约束。 | 当前通用 profile 不推断人物、法器或能力；《丹道仙途》事实只由显式 project pack 提供。`final.txt`、素材绑定、provider 请求和真实证据四层不互相冒充。 |

## 3. 为什么不能直接选 v1 或 v2

### v1 的优点与边界

v1 是最好的“创作意图和仙侠细节基线”：

- 资产在开头，人工能逐项检查实际引用；
- “贴鼎灵火”“鼎壁析出银光”“焦渣 → 药液 → 药材”等动作链没有被抽象词替代；
- 画风和原生音频写法足够明确；
- 对回溯的鼎内/鼎外边界已有可执行描述。

但它不适合作为未经编译的通用生产合同：A1/A2 编号是人工临时编号，三类资产职责没有标准化；大量通用负面词会和目标仙侠效果互相抵消；连续性主要停留在单条视频内部，不能解决上一段特写后下一段多人站位未知的问题；同时把素材操作说明和生成正文混在一起。

### v2 的优点与边界

v2 是最好的“提示词减负方向”：

- 正向结构更接近“参考素材映射 → 连续时间轴 → 声音 → 全程保持”；
- 静态外观交给参考资产，减少重复；
- 负面约束更少，降低反向压制目标效果的概率；
- 连续整数时间轴和原生音频仍然保留。

但 v2 压缩过度的地方也很明确：

- 动态特效从完整因果链缩成主链短句，模型未必知道来源、作用边界和收束；
- “全程保持”不能替代相邻生成单元的世界末态；
- “一句话概述”容易和时间轴重复，且可能把抽象总结误当作新的剧情指令；
- 图片映射仍是扁平列表，不能直接表达人物/场景/道具职责和资产状态。

因此，v2 的压缩策略应被吸收为“删重复静态描述、删大包负面词”，而不能连动态 VFX 和连续性一起删掉。

## 4. 对当前分镜规则的判断

### 已经合理、可以保留的部分

1. **媒介和模型合同明确**：横屏 `16:9`、720p、4–30 秒整数时长、原生音频和首期 `single` 模式不再漂移。
2. **两层提示词边界明确**：`final.txt` 是可审核、可复用、资产无关的母版；只有真实素材绑定并通过门禁后才编译 `submission_prompt`。这避免把逻辑绑定或离线 fixture 冒充真实素材。
3. **资产前置且分类**：人物、场景、道具/关键视觉资产各自写职责，既能给模型参考，也能让制作人员核对上传顺序。
4. **组间承接成为文字状态合同**：上一组的冻结末态先于尾帧；特写不消除画外人物，不自动重置空间、光线和声场。
5. **仙侠效果从词汇表升级为过程语法**：每个效果都要能回答“谁触发、以什么形态、沿什么路径、影响什么、产生什么反馈、怎样收束、声音是什么”。这比堆“神光、粒子、震撼”可靠。
6. **运镜不再机械化**：不要求每组有推拉摇移或数量指标，把自由度交给 Seedance 2.5；只有连续性和剧情理解确实需要时才锁定行为。
7. **负面约束收敛**：生成 prompt 只阻止本组最可能的剧情错误，完整风险留给 reviewer 检查，避免“为了防错而禁止目标效果”。
8. **审核不被格式校验替代**：真实 reviewer 仍需逐项对照剧本、分组、连续性、VFX、音频和素材边界；本地通过只说明规则可执行。

### 仍需在正式生产前盯住的地方

- **高密度组的可生成性**：G03/G07/G09/G11 等同时含多人、器物状态和 VFX 的组，文本规则正确不等于模型能在一次 4–30 秒生成中稳定完成；应优先用真实探针检查是否要拆成更短、但仍在稳定状态切断的单元。
- **身份与资产令牌**：G05→G06 等跨组处，除了文字承接，还应在编译结果中明确同一人物/同一道具的逻辑键和职责，不能只依赖“图片 N”。
- **组尾冻结的纪律**：组尾只记录已建立的末态，不提前写下一组动作；否则下一组会被错误地当成已经发生。
- **VFX 链的完整性**：静态参考图可以省略材质复述，但不能省略灵火起点、路径、药材中间态、回溯对象边界、纹样传播和收束声纹。
- **真实 provider 反馈**：当前测试没有调用 CPA、Ark、ManJuWeb 或真实 Seedance 接口，因此不能对口型、声画同步、参考资产服从度和 30 秒稳定性作生产承诺。

## 5. 推荐的最终融合结构

正式提交 prompt 建议固定为下面的顺序；`final.txt` 母版保留同样的语义顺序，但不写真实素材 token：

1. **人物资产**：本组实际引用的角色资产，以及每项只负责的身份/服装/体态职责。
2. **场景资产**：主空间和必要子区域，只负责空间布局、光线和材质锚点。
3. **道具与关键视觉资产**：元鼎、药材、灵火、回溯光层等，只负责已上传资产表达的静态身份或状态。
4. **整体画风说明**：横屏国漫 3D CG、写实材质＋克制卡通轮廓、亚洲骨相、可信 PBR、少量手绘概括、东方低饱和色盘、脸/手/口型/关键道具可读。
5. **组间空间衔接**：上一组冻结末态、本组开场锚点、画外在场者、道具/VFX/声场/轴线状态；不可确认项先重建，不猜测。
6. **横屏构图与连续整数时间轴**：左中右、前中后景、动作顺序和每个时间段的主目标。
7. **时间轴内的 VFX、光影和声音**：直接写在发生的时间段，按来源→形态→路径→作用对象→反馈→收束→声音展开。
8. **少量 `--neg`**：只列 2–5 个本组具体失败风险；不禁止 3D/CG/动漫，也不宽泛禁止火焰、粒子、银光或烟气。

不再添加“一句话概述”“视觉峰值/特效重点”“运镜强化词”或“Seedance执行提示补充”。这些信息如果是剧情必需，就放回对应时间段；如果只是审核标准，就留在 reviewer 中。

## 6. 阶段性结论与下一步

当前规则可判定为 **“规则层通过，真实生成层待验证”**：

- 适合继续保留两版探针并做 A/B 对比；
- 适合先以 EP01 或三类代表性探针做真实 provider 小样本验证；
- 不建议在没有真实视频证据前，把离线 `final.txt` 或本地状态直接包装成前 10 集生产完成；
- 如果真实测试发现效果不稳定，优先调整“单组动作密度、VFX 中间态、资产职责粒度和组间重建”，不要恢复大包式负面词或强制运镜。
